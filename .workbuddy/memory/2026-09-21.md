## 位置崩溃修复：LocationManager 无限递归（9-21 续）

用户真机点「附近」崩：`EXC_BAD_ACCESS (code=2, address=0x16b...)`（栈地址→栈溢出）。
根因：`locationManagerDidChangeAuthorization` 授权授予后调用 `startLocating { [weak self] loc in self?.pending?(loc); ... }`，`startLocating` 把 `pending` 换成这个新闭包 B；随后 `requestLocation` 回调 `didUpdateLocations` 执行 `pending?(loc)`（=B）→ B 内又 `self?.pending?(loc)`（仍是 B）→ 无限递归→栈溢出。
修复：授权后直接 `startLocating(completion: pending)`（复用用户原始回调 A），不再包一层自调用闭包。`didUpdateLocations`/`didFailWithError` 调完 A 后置 nil，无递归。
教训：CoreLocation 回调里「包装闭包再调 self?.pending」是典型递归陷阱，需避免。

## 「附近地点」不显示 · 根因与兜底（9-21 续3）

- 入口链路：`BasePostCreateViewController.openLocationPicker()` → present `LocationSearchViewController`（pageSheet .medium/.large）；`LocationSearchViewController` 已有完整 UI（标题「地点」+ 关闭、搜索框、当前位置卡片带「当前位置」标签、附近地点 section、地图选点兜底）。
- 现象根因：附近列表数据源是 `MKLocalPointsOfInterestRequest(center:radius:)`。Apple 文档明确其"仅在区域内召回 POI"，中国区/模拟器无定位时召回稀疏或为空 → `nearby` 空 → 表头与行都不渲染（`viewForHeaderInSection` 有 `nearbyLoading || !nearby.isEmpty` 守卫），于是「附近地点」整块消失。
- 修复：
  1. `fetchNearby` 结果为空时，兜底 `fetchNearbyByKeyword`：按分类词 ["美食","咖啡","便利店","超市"] 并行 `MKLocalSearch.Request`（region 3km、resultTypes .pointOfInterest、filter .includingAll），`DispatchGroup` 合并 → `dedupeSort`（3km 内过滤 + 同名去重 + 距离升序 + 取前 20）。新增 `fallbackSearches` 强引用避免 search 被提前释放。
  2. `updateStatus` 增补空态提示：`currentPoint != nil && !nearbyLoading && nearby.isEmpty` → "附近暂无地点，可搜索或在地图上选取"。
- 未用 `regionPriority`（iOS 18+），保持 iOS 15 兼容。

## 「重新选择」点击无反应 · ThemeActionSheet 全局 bug（9-21 续4）

- 现象：发作品/发帖页已选位置后点位置行 → 弹「重新选择 / 不显示位置」sheet → 点「重新选择」无反应，LocationSearchViewController 不弹出。
- 根因（UIKit 经典坑）：`ThemeActionSheet.didTapAction` 先 `onSelect?(tag)` 再 `dismiss`。`onSelect` 内 `openLocationPicker()` → `present(nav)`，但此刻 presenting VC 仍在 present 该 sheet，UIKit 报 "presentation is in progress" 并忽略新 present，随即 sheet dismiss → 新页面一起消失。
- 佐证：`PostDetailViewController.didTapMorePost` 的 onSelect 曾用 `DispatchQueue.main.asyncAfter(+0.35)` 延迟等待 sheet dismiss 再 present —— 正是绕开同 bug 的补丁。
- 修复：`ThemeActionSheet.didTapAction` 改为先 `dismiss(animated:false) { handler?(index) }`，在 completion 中回调（局部捕获 `let handler = onSelect` 避免弱引用时序问题）。这同时让所有"在 sheet 中选完再 present"的调用方（发布类型、选择班级、删除弹框等）天然正确，无需各自加延迟。
- 连带清理：`PostDetailViewController` 移除冗余的 `asyncAfter(+0.35)` 补丁。
- 教训：任何 **present 新页面** 的动作若来自一个已 present 的 sheet/alert 的回调，都应在 dismiss completion 中触发，否则会被 UIKit 吞掉。
- 验证：BUILD SUCCEEDED + install/launch 模拟器（PID 55892）。
- 提醒用户：若 LocationSearchViewController 内「确认」后位置未回填/页面未关闭，那是另一处（picker 自身 dismiss 逻辑），需另查。

## TabBar 背景改为透明（9-21 续5）

- 用户要求把 iOS tabbar 背景设为透明。原 `BaseTabBarViewController.configureTabBar()` 用 `isTranslucent=false` + `backgroundColor=Theme.Color.surface`（不透明）。
- 改法（iOS 13+ 正确姿势）：`UITabBarAppearance` → `configureWithTransparentBackground()` + `backgroundColor=.clear` + `shadowColor=.clear`（去顶部分隔线）+ `backgroundEffect=nil`（纯透明非毛玻璃）；同时赋给 `standardAppearance` 与 `scrollEdgeAppearance`（iOS15 滚动到顶不"弹回"不透明）；`isTranslucent=true`（沉浸式，内容可延伸至 bar 下）。
- 注意：若设计想要"毛玻璃"半透明而非纯透明，可改用 `backgroundEffect = UIBlurEffect(style:)` 保留模糊。
- 验证：BUILD SUCCEEDED + install/launch 模拟器（PID 57947）。

## 聊天发送消息不立即显示（9-21 续6）

- 现象：ChatViewController 聊天页，点发送后气泡不立刻出现，退出重进才看得到。
- 根因：原 `send` 是"等接口回包才插入"的被动模式——`MessageService.sendMessage` 成功回调里 `if let message` 用 `json["data"]` 解码 `ChatMessage`；若后端 `data` 没回传可解码消息体（message_id 缺失/结构不符），`message` 为 nil，本地 `insert` 压根不发生 → 气泡不显示。
- 修复（乐观更新）：`send` 点发送即构造临时 `ChatMessage`（messageId 前缀 "local-"，senderId=我的 userId，createdAt 用 `yyyy-MM-dd HH:mm:ss` 对齐 MessageTimeFormatter 解析），立即 insert 到 serverMessages 头部并 rebuildDisplay；输入框先清空。接口成功且带回真实消息 → `replaceTemp` 移除临时消息并插入真实消息（按 messageId 去重）；接口失败 → 移除临时消息并还原输入框内容 + toast。接口回包为 nil 时保留临时消息，等 WS 回包对齐。
- WS 回包对齐：`didReceiveChatMessage` 新增——同 id 已存在则跳过；若这是自己消息且本地仍有 "local-" 临时消息，直接替换该临时消息（避免重复气泡），否则正常 insert。
- 注意：ChatMessage 为 let 结构体，Swift 自动生成逐一成员构造器，临时消息可直接 `ChatMessage(...)` 初始化。
- 验证：BUILD SUCCEEDED + install/launch 模拟器（PID 63192）。

## 会话列表返回不刷新 · 导致最后一条消息不一致（9-21 续7）

- 现象：在聊天详情发消息（乐观更新已显示）后返回会话列表，列表"最后一条消息"仍是进聊天前的旧内容，与详情不一致。

- 验证：BUILD SUCCEEDED + install/launch 模拟器（PID 65189）。

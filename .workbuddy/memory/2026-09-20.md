## 帖子位置 · Xcode 编译报错修复（2026-09-20 续3）

用户贴出 Xcode 报错，定位到上一轮"App 端完成"记录仍有两处**实际漏写**，导致根本编译不过：
1. `HomeModels.swift` 引用 `PostLocation` 但 **struct 从未真正写入**（grep 全工程 `struct PostLocation` 零匹配）→ `PostItem` 因引用缺失类型而不 conform Decodable，且 line 249 "Cannot find type 'PostLocation'"。
   - 修复：在 `PostItem` 前补 `struct PostLocation: Codable { latitude, longitude, name: String? }`。`name` 用可选，因为后端 `normalizePost` 返回 `name: post.location_name || null`（逆地理编码失败时可为 null），非可选会在解码时整条 PostItem 失败。
   - 注意后端 normalize 的地点名 JSON key 是 **`name`**（不是 `location_name`），与 PostLocation 属性名一致，Codable 可直接解；落库列仍是 `location_name`。
2. `PostDetailViewController` 的 `PostDetailSection` 枚举加了 `.location`，但 `cellForRowAt` 与 `estimatedHeightForRowAt` 的 `switch` **都没有 `case .location`** → 非穷尽 switch 编译错误（上一轮漏接）。
   - 修复：两处 switch 补 `case .location`（cell 走 `PostLocationCell.configure(name:distance:)`，`name` 传 `post?.location?.name ?? ""`、`distance` 传 `post?.distanceText`）；estimated 返回 56。
3. `BasePostCreateViewController.locationCell` 原 `cell.detail = loc.name` 因 `name` 改可选需改 `loc.name ?? ""`（`PickerCell.detail` 为 `String`）。

结论：前几轮位置相关改动因沙箱无 Xcode 一直未编译，本次才暴露。所有"完成"结论须以 Xcode 真编译为准。

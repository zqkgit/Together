# 艺启 · 四端开发计划（后端 + iOS + Web + 小程序）

> 版本：v1.0（2026-09）
> 依据：`backend-design.html`（DB+API v1.3）· `app-prototype.html`（51 屏）· `platform-admin-console.html` / `web-admin-plan.html`（Web）· `开发准备清单.md`
> 总周期预估：**12 周**（不含第三方账号审批等待期，审批需提前并行启动）

---

## 一、总体架构与端定位

```
                     ┌──────────────┐
      iOS（全功能） ──┤              │
  小程序（轻量获客）──┤  Node.js API │── MySQL 8（9 域 42 表）
  Web 管理端（B 端）──┤  /v1 + /admin│── Redis（验证码/黑名单/缓存/WS）
                     └──────────────┘
```

| 端 | 技术栈 | 定位与范围 |
|---|---|---|
| **后端** | Node.js + Express + Sequelize + MySQL 8 + Redis | 唯一业务中心。`/v1` 服务 iOS 与小程序（`X-Client: ios\|wxapp` 区分），`/admin` 服务 Web 管理端 |
| **iOS** | Swift + SwiftUI（iOS 16+），AFNetworking/URLSession + Combine | **全功能主端**：家长/老师/工作室三角色，对齐 51 屏原型全部功能 |
| **小程序** | 微信原生（WXML/WXSS/TS） | **轻量获客端**：课程浏览/搜索/详情、报名支付（小程序支付）、订单、分享分销落地页；不做发帖/私聊/认证等重功能 |
| **Web 前端** | React 18 + Vite + Ant Design（按设计系统定制暖色主题）+ React Query | 工作室经营后台 12 模块 + 平台运营治理（认证审核/结算分账） |

**四端分工原则**：
- 交易闭环（浏览→支付→课时）iOS 与小程序**全等**，共用 `/v1` 订单/支付接口，仅支付方式不同（App 支付 vs 小程序支付，同一商户号）
- 内容与社交（广场/发帖/私聊/成长档案）**只在 iOS**
- B 端经营与治理**只在 Web**
- 分销分享链路：iOS 发帖/课程 → 生成小程序码 → 新用户从小程序落地 → 引导下载 iOS

## 二、开发阶段（6 个阶段 · 12 周）

### 阶段 0 · 工程启动（第 1 周）

| 任务 | 负责 | 产出 |
|---|---|---|
| OpenAPI 契约：`backend-design.html` 转 Swagger，定统一响应包裹 + 错误码表（含 `40401`） | 后端 | `openapi.yaml` + Apifox mock 空间 |
| 设计 token 包：色板/字阶/圆角/阴影导出，三端共享 | 设计/前端 | `shared/tokens`（CSS 变量 + Swift + WXSS 三份产物） |
| 四端仓库与 CI：Monorepo（`server / ios / wxapp / admin-web / shared`），ESLint/SwiftLint，自动构建 | 全员 | 可跑通 Hello World 的四端骨架 |
| 环境：本地/测试环境 MySQL + Redis、`.env` 密钥规范 | 后端 | docker-compose 一键起本地依赖 |
| **并行**：提交微信开放平台/支付商户/短信/备案申请（见准备清单） | 负责人 | 审批单号跟踪表 |

**里程碑 M0**：四端骨架可运行，契约评审通过。

### 阶段 1 · 账号体系（第 2–3 周）

| 端 | 范围 |
|---|---|
| 后端 | `/auth` 全模块：send-code（is_new_user）、login、login-password、register、wx-login、logout、refresh、role/switch、me/profile；users/user_roles/children 表 migrations；JWT 中间件 + Redis 黑名单 |
| iOS | 欢迎页 → 手机号页（验证码/密码双模式）→ 注册引导三步 → 身份认证页；三角色 TabBar 导航壳（NO_TAB 规则） |
| 小程序 | 微信一键登录（`wx.login` → `/auth/wx-login`）+ 手机号快捷绑定（getPhoneNumber）；未绑定则引导 |
| Web | 管理员登录（独立账号体系或扫码，一期可先账号密码）+ RBAC 路由守卫 |

**里程碑 M1**：四端登录链路联调通过（验证码用测试环境真实短信或控制台回显）。

### 阶段 2 · 交易闭环 = MVP（第 4–6 周）⭐ 核心

| 端 | 范围 |
|---|---|
| 后端 | courses/classes/schedules/orders/payments/order_lessons/lesson_log 全表；`/courses`、`/orders`、`/orders/:id/pay`、支付回调（微信 App 支付 + 小程序支付 + 支付宝）、课时到账事务 |
| iOS | 首页推荐、搜索、课程详情、报名支付（Apple 侧走微信/支付宝）、支付成功页、订单列表/详情、我的孩子 + 课时表 |
| 小程序 | 课程列表/详情/报名支付/订单——MVP 与 iOS 交易链路等价（**这是小程序的生存理由：分享落地即可付费**） |
| Web | 工作室课程管理（发布/编辑/上下架）、订单列表 |

**里程碑 M2**：真机真钱跑通「浏览→支付→课时到账→我的孩子可见」，iOS 与小程序双端。

### 阶段 3 · 内容与消息（第 7–8 周）

| 端 | 范围 |
|---|---|
| 后端 | posts/feed/plaza/互动；`mark-students` 消课三入口统一写 `lesson_log`；conversations/messages（WebSocket）；teacher_applications 认证流 |
| iOS | 广场/发帖/帖子详情、成长档案（出勤/雷达/作品墙）、私聊、老师认证申请与状态页 |
| 小程序 | 只读：帖子/课程分享落地页（内容引流，不做发布） |
| Web | 老师认证审核（工作室侧） |

**里程碑 M3**：发帖→标记学生→扣课时→家长收到通知 全链路演示通过。

### 阶段 4 · 经营与治理（第 9–10 周）

| 端 | 范围 |
|---|---|
| 后端 | 分销返利（钱包/提现）、退款审核与按比例折算、结算 `settlements`、`/admin` 工作室 12 模块 + 平台治理接口 |
| iOS | 收益中心、提现、退款申请/进度、工作室端经营概览 |
| Web | 工作室经营后台全模块（概览/学员/老师/财务/返利设置）、平台端认证审核 + 结算分账（对齐 `platform-admin-console.html`） |
| 小程序 | 退款申请 + 进度查询 |

**里程碑 M4**：功能冻结，进入测试。

### 阶段 5 · 打磨与上线（第 11–12 周）

- **边界态补齐**：空态/骨架屏/错误态（设计系统已欠账，此阶段强制覆盖）
- **合规**：正式协议替换、未成年人隐私合规自查、安卓无关（本计划仅 iOS）、**App Store 审核材料**、小程序类目资质（教育-培训，可能需办学许可，提前确认）
- **测试**：原型逐屏 UAT（App）+ 支付/退款资损用例专项 + 接口自动化冒烟
- **上线**：测试环境全量验收 → 生产发布 → 小程序审核提审 → App Store 提审（预留 1 周审核缓冲）

## 三、并行开发机制（防阻塞的关键）

1. **契约先行**：阶段 0 定稿 OpenAPI 后，后端未完成的接口由 Apifox mock 顶替，三客户端不停工
2. **每周联调日**（建议周四）：当周新增接口真实联调，问题不过周
3. **错误码表单一来源**：`shared/error-codes`，四端引用同一份
4. **设计走查**：每阶段结束按原型做视觉走查，偏差当阶段清
5. **分支策略**：`main`（可发布）/ `dev`（联调）/ feature 分支，PR 必须过 CI

## 四、人力建议（最小配置 4–5 人）

| 角色 | 人数 | 说明 |
|---|---|---|
| 后端 | 1–2 | 阶段 2 起若单人会成为瓶颈，建议 2 人（一人业务一人支付/结算） |
| iOS | 1 | SwiftUI 熟手；51 屏组件复用度高 |
| 小程序 | 1 | 可由前端兼任（阶段 2–4 工作量中等） |
| Web 前端 | 1 | 阶段 1 轻、阶段 4 重 |
| 设计/测试 | 各 0.5 | 设计供 token 与边界态；测试从阶段 2 介入 |

## 五、风险清单

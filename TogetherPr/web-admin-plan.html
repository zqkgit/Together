艺启 · 儿童艺术教育平台 — Web 管理端（工作室后台）技术栈与功能规划
① 管理端定位与使用者
管理端（B 端）同时承载两类使用者：平台员工（运营整盘：工作室认证、全平台风控、结算分账、平台规则）与工作室员工（老板 / 运营 / 教务，经营单店）。两者共用同一套 Web 后台，靠角色 + 数据范围区分——平台角色跨工作室（ALL），工作室角色仅本租户。老师不设 Web 角色：老师在 App 端完成发帖/消课/点评，Web 端的班级/学员/消课记录由 studio_owner/ops 管理。
与移动端关系：移动端负责「家长购课 / 老师发帖消课 / 学员看成长」，管理端负责「配课、排班、审单、算账、看数据 + 平台治理」。共享同一套数据库与业务表，管理端以「写 + 经营/治理分析」为主，移动端以「读 + 业务触发」为主。
平台级：platform_super 平台超管 platform_ops 平台运营 工作室级：studio_owner 工作室主 studio_ops 运营/教务
② 技术栈（前端已定 Vue3 + Element Plus）
🧱 前端
  • 框架：Vue 3（Composition API）+ Vite + TypeScript
  • UI 组件库：Element Plus（表格 / 表单 / 弹窗 / 上传 / 树选，中后台开箱即用）
  • 状态/路由/请求：Pinia + Vue Router 4 + Axios（统一拦截器：token、错误、loading）
  • 图表：ECharts（经营看板、营收趋势、出勤率）
  • 工具：dayjs（时间，与后端一致）、vue-clipboard3（分销链接复制）、富文本（动态/公告，可选 @wangeditor）
  • 权限：前端菜单/按钮级权限由后端返回的角色+权限码驱动（v-permission 指令 + 动态路由）
🧱 后端（复用现有 Node/Express，新增 /admin 模块 + RBAC）
  • 复用：Node.js + Express + MySQL + Sequelize + Redis + dayjs + bcrypt + crypto + cors + ali-oss + 雪花 bigint ID
  • 新增：/admin/* 路由分组、RBAC 中间件（菜单/接口/数据范围）、操作审计日志、Excel 导出（exceljs）
  • 鉴权：管理端独立 JWT（/admin/login 签发 admin token），与移动端 X-Role 体系隔离；所有写操作强制带 studio_id 行级过滤
  • 实时：WebSocket 复用（订单提醒、退款待办、新请假推送给教务）
复用现有后端 + RBAC 的理由：省一套服务与运维，管理端与 C 端共享业务表与事务（退款审核直接改 refunds、手动消课直接动 lesson_log），数据天然一致。代价是用路由前缀 + 权限中间件做好边界隔离。
③ 权限模型（RBAC + 行级数据隔离）
层级角色数据范围典型权限
平台级
艺启平台员工		platform_super全部工作室（ALL）全部：工作室认证/封禁、全平台数据、结算分账、平台规则与收费
platform_ops全部工作室（ALL）工作室入驻审核、全平台内容风控、平台公告/活动、结算初审
工作室级
单工作室员工		studio_owner本工作室全部：课程/班级/排课/订单/退款/分销/财务/员工账号
studio_ops本工作室排课、学员、订单处理、退款初审、内容审核、消息
  • 两级管控：平台级（跨工作室，运营整盘）+ 工作室级（单租户）。平台角色登录后可「下钻某工作室」查看其后台；工作室角色只能看本工作室。
  • 三级粒度：菜单权限（能否看到页面）→ 接口权限（能否调 API）→ 按钮权限（能否点「审核/导出」）
  • 数据范围：工作室角色（owner/ops）查询自动注入 WHERE studio_id = ?；平台角色 studio_id = ALL（可下钻具体 studio_id）。App 端老师数据按 teacher_id 隔离（Web 端不另设老师角色）。
  • 表：admin_users / roles / permissions / role_permissions / admin_studio_map / audit_logs
④ 功能模块规划（12 大模块）
A. 工作台 Dashboard
经营概览卡片（今日订单/消课数/新增学员/待办：请假·退款·认证）、近 30 天营收趋势(ECharts)、班级出勤概览、待办清单一键处理。
B. 课程管理
课程 CRUD、封面/介绍/价格/课时包编辑、上架下架、课程分类；关联老师可选的授课范围。
C. 班级管理
班级列表、新建班级（关联课程+老师+排课）、班级详情（学生名单、课表、消课进度、剩余课时）。
D. 排课管理
周课表视图（日历/甘特）、新增排课、调课/代课、老师-教室冲突检测、批量排课。
E. 老师管理
老师列表、入驻资质审核、课表与带班、请假/排班、授课评价。
F. 学员管理
学员列表（关联家长）、报名/转班记录、课时余额、请假记录、成长档案查看、手动消课/调课。
G. 订单与交易
订单列表（购课/续费）、支付流水、退款审核工作流（申请→审核→打款）、发票管理。
H. 分销管理
分销员（家长/推广人）列表、分销链接生成、返利规则配置、返利结算与提现审核。
I. 内容管理
动态/作品审核（下架/精选）、话题管理、社区氛围与举报处理。
J. 消息与通知
通知模板配置、推送记录、系统公告、WebSocket 实时提醒开关。
K. 工作室设置
工作室资料、资质认证（营业执照/办学许可）、校区/门店、员工账号与 RBAC、收款账户。
L. 财务对账
营收/退款/分销结算报表、按日/月对账、Excel 导出、提现对账。
④B 平台运营模块（平台角色专属 · 跨工作室）
P1. 工作室认证/入驻
入驻申请列表、资质审核（营业执照/办学许可/师资）、工作室上下架/封禁、生命周期管理。
P2. 全平台数据看板
总 GMV、新增工作室/学员、各工作室排行、转化漏斗（ECharts 全平台视角）。
P3. 平台内容风控
全平台动态/作品/举报审核、敏感词库、全网下架与回溯、违规工作室处置。
P4. 工作室结算/分账
平台与服务商的结算单、抽成配置、对公打款、开票与对账（平台收付侧）。
P5. 平台分销与抽成
全局分销规则、平台↔工作室分润比例、分销员跨店归属与反作弊。
P6. 平台公告/运营活动
全站推送、活动/专题配置、Banner 与首页运营位、平台级短信/通知模板。
P7. 平台收费配置
服务费/抽佣比例、套餐与权益、入驻门槛与认证要求配置。
P8. 平台员工与权限
平台侧 admin 账号、角色分配、操作审计，可「下钻」任意工作室后台。
模块分两级：工作室级 12 模块（A–L，单租户经营）+ 平台级 8 模块（P1–P8，跨工作室治理），均与后端表一一对应（courses / classes / schedules / orders / refunds / distributions / works / growth_* / studio_* / teacher_* / audit_logs / platform_config 等）。管理端「写」这些表，移动端「读 + 业务触发」。

⑥ 与移动端 API / 表的复用关系
管理端「写」、移动端「读 + 业务触发」共享同一批表；平台角色可跨工作室读写（studio_id = ALL，可下钻单店），工作室角色仅本租户。如「手动消课」「退款审核」由管理端在事务内直接修改 lesson_log / refunds，移动端实时可见。
⑦ 实施阶段（里程碑）
M1 脚手架+权限
Vite+Vue3+Element Plus 工程、Pinia/Router、Axios、RBAC 登录、动态菜单、工作台雏形。
M2 教务核心
课程、班级、排课（周课表）、老师管理 CRUD 与审核。
M3 交易与钱
订单、支付流水、退款审核工作流、分销与提现结算。
M4 内容与数据
内容审核、消息通知、ECharts 经营看板、Excel 对账导出。
M5 打磨
细粒度按钮权限、操作审计日志、性能与体验、灰度。
平台级模块（P1–P8）建议作为独立并行轨道推进：优先做 P1 工作室认证 + P2 全平台看板 + P4 结算（支撑「工作室入驻→经营→平台抽成回收」闭环）；P3/P5/P6/P7/P8 随规模逐步补齐。平台与工作室共用同一套 RBAC 与 /admin 路由，仅数据范围不同（ALL vs 单 studio_id）。
⑧ 关键技术点 / 风险
  • 隔离行级数据隔离（租户）：所有列表/写接口中间件自动注入 studio_id；平台角色为 ALL（可下钻单店），工作室角色锁定本工作室，防越权看别家数据。
  • 并发并发消课/退款：沿用移动端方案——transaction + 行锁（SELECT ... FOR UPDATE），管理端手动调课同样走此路径防超扣。
  • 幂等退款/支付回调：以 out_trade_no / 退款单号做幂等键，Redis 防重。
  • 上传ali-oss 直传：后端签发 STS/签名 URL，前端直传，仅存 URL 到库。
  • 审计操作日志：关键写操作（审课/审退款/改课时）落 audit_logs，便于追溯。
  • 权限前端不信任：菜单可隐藏，但接口仍需后端 RBAC 二次校验（防绕过）。

本文件为单文件、零依赖 HTML，可换电脑直接打开。规划基于已定的移动端后端栈（Node+Express+MySQL+Sequelize+Redis+dayjs+bcrypt+crypto+cors+ali-oss+雪花 ID）与 Vue3+Element Plus 前端框架。管理端含平台级（P1–P8）与工作室级（A–L）两级。下一步：① 立 Vite 工程与 RBAC 登录（含 platform/studio 双层级）；② 落 admin_users/roles/permissions/audit_logs/platform_config 表；③ 工作室 M1→M5 与平台 P1/P2/P4 并行推进。

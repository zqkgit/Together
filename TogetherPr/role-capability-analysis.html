艺启 · 儿童艺术教育平台 — 角色能力对照分析：App 端（C 端）↔ Web 管理端（B 端）
① 为什么要做对照
艺启有两个端、八类使用者：
· App 端 是面向家长 / 老师 / 工作室管理员的 C 端移动应用（PRD 共 48 页、3 种角色、10 大模块），核心动词是「触发业务」——购课、发帖消课、申请退款、发作品、分销。
· Web 管理端 是面向工作室员工的 B 端经营后台（12 模块 A–L），核心动词是「配置与经营」——配课、排班、审单、算账、看数据。
· Web 平台端 是面向平台员工的治理后台（8 模块 P1–P8），核心动词是「治理整盘」——工作室认证、全平台风控、结算分账、平台规则。

两端共享同一套数据库与业务表：App 负责"产生数据 + 消费展示"，Web 负责"管理数据 + 写回状态"。本分析的目的就是把每个 Web 角色的权限与 App 端的能力逐一对齐，确保闭环无遗漏、无越权。
② 角色全景：App 三角色 ↔ Web 四角色（平台 2 + 工作室 2）
📱 App 端（C 端 · 一账号多角色切换）

👨‍👩‍👧 家长 Parent

平台主要消费者，C 端纯用户
购课、管理订单/退款、查看孩子作品与成长、发布孩子作品、分销返利、关注、收通知。

👩‍🏫 老师 Teacher

需资质认证，课后记录者
发帖记录+标记学生+自动扣课、个人主页作品集、小程序分享、资质认证、收通知、看本人课表/学生。

🏢 工作室管理员 Studio Admin

移动端的「轻量经营入口」
创建/管理工作室、发布管理课程、邀请老师、处理订单退款、设置分销比例、工作室主页、提交资质审核。
💻 Web 端（B 端 · 按角色+数据范围隔离）

🛡️ platform_super 平台超管

跨全部工作室（ALL）
全平台权限：工作室认证/封禁、全平台数据、结算分账、平台规则与收费。

🧭 platform_ops 平台运营

跨全部工作室（ALL）
入驻审核、全平台风控、平台公告/活动、结算初审、平台分销抽成配置。

🔑 studio_owner 工作室主

本工作室（单租户）
12 模块全权：课程/班级/排课/订单/退款/分销/财务/员工账号。

🗓️ studio_ops 运营/教务

本工作室（单租户）
排课、学员、订单处理、退款初审、内容审核、消息；课程/财务/设置受限。
一句话映射： App「工作室管理员」≈ Web 的 studio_owner / studio_ops（App 是轻量移动入口，Web 是完整后台）； App「老师」不登录 Web 管理端——老师在 App 端完成发帖/消课/点评；Web 端班级/学员/消课记录由 studio_owner/ops 承担； App「家长」在 Web 端没有对等管理角色（纯 C 端），Web 通过「学员管理 F」间接看到其关联数据； App 端没有平台角色，但 App 里的所有工作室/交易数据由 Web 的 platform_* 治理。

⑥ 数据流向：谁产生 · 谁管理 · 谁消费
闭环铁律：App 端只产生业务与消费展示，所有"管理动作"（审核/配置/对账/治理）都落在 Web 端；Web 端写回的状态通过 WebSocket/接口实时回写 App。家长作为纯 C 端，其数据由 Web「学员管理 F」间接管理，不存在家长的管理端账号。
⑦ 对应原则小结
  • 轻量入口 vs 完整后台：App 的「工作室管理员」是移动端轻量入口，Web 的 studio_owner/ops 是完整后台；老师不设 Web 角色——老师在 App 端完成发帖/消课/点评，Web 端由 studio_owner/ops 管理班级、学员与消课记录。
  • 家长无管理角色：家长是纯 C 端消费者。Web 管理端没有"家长管理员"，家长相关数据通过「学员管理 F」+「分销 H」间接处理（订单、退款、返利、成长档案）。
  • 平台治理闭环：App 没有平台角色，但 12 项业务里「工作室入驻 / 平台结算 / 平台风控 / 平台抽成」三个治理环节只在 Web 平台端发生，对应 P1 / P4 / P3 / P5。
  • 权限不信任前端：前端菜单/按钮权限只是体验层，真正的隔离靠后端 RBAC 中间件（studio_id 行级 + teacher_id 二级隔离 + 平台 ALL 下钻）。
  • 一致的数据源：两端共用同一批表，App 业务触发与 Web 管理写回都落在同一事务，保证家长在 App 看到的课时/退款/返利状态与 Web 后台完全一致。
待办：若要把「工作室管理员」App 轻量入口与 Web studio_owner 彻底对齐，建议明确 App 工作室端只保留「发布课程 / 处理退款 / 设返利比例 / 看概览」四类高频操作，其余一律引导到 Web 后台，避免两端功能重复、权限混乱。

## 二、合规文档（涉及儿童数据，必须前置）

平台核心数据是孩子的照片、成长档案、课堂作品，属**未成年人个人信息**，合规要求高于一般 App：

- [ ] **正式版《用户协议》《隐私政策》**——替换原型中的演示文案（原型入口已预留：欢迎页协议勾选 + 底部条款面板），上线前需法务定稿
- [ ] **未成年人个人信息保护规则**：监护人同意机制（家长注册即默认监护人身份，需明示）、儿童数据加密存储、账号注销时的数据删除权
- [ ] **协议同意留痕**：注册/登录写入 `users.terms_agreed_at`（表结构已含该字段）
- [ ] 小程序上架需完成**微信隐私协议声明**与类目资质核验

## 三、工程基建（1–2 天可搭好）

### 3.1 仓库结构（Monorepo）

```
yiqi/
├── server/        # Node.js + Express + Sequelize + migrations（REST /v1 + /admin）
├── ios/           # iOS 主端（Swift + SwiftUI，对齐 app-prototype.html 51 屏）
├── wxapp/         # 微信小程序（原生，轻量获客：浏览/报名/支付/分享落地）
├── admin-web/     # Web 管理端（React + Vite，工作室后台 + 平台治理）
├── shared/        # 四端共用：设计 token、常量、错误码、类型定义
└── docs/          # 本目录现有设计/后端文档归档
```

### 3.2 环境与规范

- **三套环境**：本地 / 测试 / 生产，各自独立 MySQL 8 + Redis
- **密钥管理**：支付密钥、JWT Secret、短信 AK 一律走 `.env`，不入库；小程序 appid 与 iOS bundle id 纳入环境配置
- **接口契约**：将 `backend-design.html` 的接口表转为 **OpenAPI/Swagger**（含统一响应包裹格式与错误码表，如已出现的 `40401` = 未注册号码），作为前后端并行开发的唯一依据
- **代码规范**：ESLint + Prettier、Conventional Commits、Sequelize migration 模板、JWT 中间件 + 统一响应包装器

## 五、开发分期与验收标准

| 期 | 范围 | 关键链路 |
|---|---|---|
| **一期（MVP）** | 账号 + 交易闭环 | 登录注册（欢迎页 → 手机号页 → 验证码/密码 → 引导完善）→ 课程浏览/搜索 → 报名支付 → 课时到账 → 我的孩子 |
| **二期** | 内容与师资 | 广场/发帖/消课联动（`lesson_log` 统一账本）、消息私聊、老师认证申请流 |
| **三期** | 经营与治理 | 工作室经营后台（Web 12 模块）、分销返利、平台结算分账、平台治理 |

**验收标准**：以现有高保真原型为 **UAT 基准**——每期交付的 App 行为需与原型交互逐屏对齐；接口行为以 OpenAPI 文档为准。

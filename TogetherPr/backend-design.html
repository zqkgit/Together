艺启 · 儿童艺术教育平台 — 后端接口与数据库设计（覆盖 PRD 48 页面 / 10 模块 · 三角色）

后端设计文档

本文给出「艺启」的服务端整体方案：数据库表结构（约 42 张表，分 9 个域）、RESTful 接口清单（App /v1 + 管理端 /admin），以及核心业务的时序约定。设计对齐现有 PRD 与两端八角色：App 三角色（家长 / 老师 / 工作室）「触发业务」，Web 四角色（platform_super / platform_ops / studio_owner / studio_ops）「配置经营 + 治理写回」。覆盖课时自动扣减、按比例退款、分销返利、平台结算分账、家校私聊。

技术选型与约定

🧱 技术栈（已定）
  • 运行/框架：Node.js + Express（REST 路由 + 中间件校验/鉴权）
  • ORM：Sequelize（模型关联、事务、paranoid 软删、migrations）
  • 数据库：MySQL 8（bigint 主键、json 存数组/动态维度）
  • 缓存/会话：Redis（验证码、JWT 黑名单、热点 Feed、WS 状态）
  • 工具库：dayjs(时间) · bcrypt(密码哈希) · crypto(签名/令牌) · cors(跨域) · ali-oss(头像/作品/资质)
  • 主键：bigint 雪花算法自定义生成器（避免自增暴露规模）
  • 支付：微信支付 V3 + 支付宝开放平台
  • 鉴权：JWT（Access+Refresh），角色存于 claims
📐 通用约定
  • Base URL：https://api.yiqi.com/v1
  • 角色：parentteacherstudio，请求头 X-Role 切换
  • 时间：ISO 8601 UTC，MySQL datetime 存 UTC；读写统一用 dayjs
  • 枚举：状态/类型用 smallint 存码值（见各表说明），Sequelize 用 INTEGER + 常量对象映射
  • 分页：?page=1&size=20，返回 {list,total,page,size}
  • 响应：{code,msg,data}，code=0 成功
  • 软删除：Sequelize paranoid:true 自动维护 deleted_at
  • ID：雪花 bigint 生成器（beforeCreate hook 写入），文中以 _id 表示
字段标注：PK=主键 · FK=外键 · ∅=可空 · 类型列如 bigint/varchar/json/datetime/smallint（枚举码值）。
🔧 Sequelize 落地约定
  • 模型目录：models/ 每表一文件，index.js 用 sequelize.import 汇总并建 associate() 关联
  • 主键：id:{type:Sequelize.BIGINT, primaryKey:true}，beforeCreate hook 调雪花生成器赋值；关闭自增
  • 关联：belongsTo / hasMany 表达 FK（如 Course.belongsTo(Studio)）；through 处理多对多
  • JSON 字段：Sequelize.JSON 存 images / scores / subjects 等数组与对象
  • 事务：扣课时、退款等用 sequelize.transaction + 行锁（findOne({lock:true})）防并发超扣
  • 时间：timestamps:true 自动 createdAt/updatedAt（datetime UTC），paranoid 软删
  • 密码：bcrypt.hash 加盐存储，登录用 bcrypt.compare；微信用户可空
  • 文件：头像/作品/资质经 ali-oss 上传，库内只存 URL

⑨ 平台治理 / 结算 / 审计

核心业务流程（时序要点）

⓪ 登录 / 注册 → 引导（对齐 App 欢迎页 + 手机号登录页）

POST /auth/send-code→ is_new_user?→ 新: POST /auth/register→ PUT /me/profile 完善资料→ 选身份 + POST /children→ 老师/工作室: POST /auth/role/apply
老用户两条路：POST /auth/login（验证码）或 POST /auth/login-password（密码），成功后按 roles[] + current_role 重建导航壳；POST /auth/logout 拉黑 refresh_token。注册前置条件：客户端勾选协议（写 users.terms_agreed_at）。

① 购课 → 课时到账

选课/选孩子→ POST /orders→ POST /orders/:id/pay→ 支付回调→ orders.status=进行中→ 课时到账(order_lessons)

② 消课（统一账本 · 三入口汇一）

// 发帖扣课 POST /posts/:id/mark-students  {child_ids:[...]}（source=1）
// 出勤扣课（source=2）/ 手动消课 POST /admin/studio/students/:id/consume（source=3）同构
for each child:
  tx = 事务 + 行锁 order_lessons
  order = 找到该 child 在 course 的有效订单（未过期）
  lesson_log 插入 {source, type=1正常, delta=-1}      // 唯一权威账本
  order_lessons.consumed = Σ(lesson_log.delta)        // 回写余额，杜绝双计
  通知 家长: "孩子·课程·已上第N课时·剩余M课时"
// 请假生（leave_requests.status=1 且命中本节）置灰不可勾选；补课节次 source=2 时 delta=+1 冲回
消课三入口（发帖 / 出勤 / 手动）全部写 lesson_log 后回写 order_lessons.consumed，同一事务保证账实一致；post_students.deducted、attendance.status 只作「触发源 + 去重标记」，不再是独立计数器。

③ 退款（按实付单价折算）

家长申请→ unit_price=实付÷总课时→ refund=单价×剩余课时→ 工作室审核→ 原路退回→ 回扣已发返利
退款规则：单价 = paid_amount ÷ total_lessons（分，向下取整），课时包打折按实付折算，避免多退。已发放返利从钱包余额扣回（commission_records.status=4）；余额不足记 wallets.debt 欠款，后续返利到账先抵 debt 再入 balance（PRD 8.4）。

④ 分销返利闭环

家长发作品关联课→ 他人经 link 购买→ 成单记录 commission→ 订单完成+7天→ 到账钱包→ 提现微信零钱
反欺诈：通过设备指纹/IP/账号关联识别「自己买自己链接」，不计入返利（PRD 8.4）。

⑤ 平台结算分账（Web 平台端 P4）

月初批量生成月结算单→ net=收入−退款−分销→ payable=net×(1−抽成)→ 平台初审→ 对公打款→ 标记到账 / 异常重打
结算单关联 settlement_orders 明细可追溯；打款/重打全程写 audit_logs；异常（户名与执照不符）退回工作室核对 studio_settlement_accounts。

⑥ 工作室封禁下游处置

平台封禁 studio→ 课程全部下架→ 停收新单→ 存量课时继续履约→ 冻结违规待结算款→ 解封后恢复
封禁只停「新增交易」，不终止存量履约：已购订单课时继续可消、已生成结算单正常打款、未到账返利到期照发；仅违规工作室的未结算款项可冻结待处理。解封由 platform_super 复核。

交付说明

本文件为单文件、零依赖 HTML，可换电脑直接打开。数据库约 42 张表 / 9 域、接口约 60 个（App /v1 + 管理端 /admin），覆盖 PRD 全部 10 模块、两端八角色与三条资金闭环（消课 / 退款 / 结算分账）。下一步可据此：① 用 Sequelize migrations 落地表结构（含雪花 ID 生成器与索引）；② 对每个接口补 Request/Response Schema（OpenAPI）；③ 补幂等、并发扣课时（事务+行锁）、防超卖、返利到账定时任务与结算对账重跑策略。

# 线下资金模式改造方案（定稿）

> 产品定位：**SaaS 课时 & 学员档案工具**，不是课程交易平台。
> 平台**全程不碰任何学费资金**：App 内不内置支付、不唤起付款、不展示收款码；学费 / 退款 / 推广佣金均由机构与家长、机构与老师**线下结算**，系统只做「台账 + 凭证 + 双方手动确认」。
>
> 状态：**定稿（8 项决策已全部拍板）**。本文为后端、Web、iOS、小程序各端资金相关逻辑的唯一口径。
> 更新：2026-09-22。

---

## 〇、八条锁定决策（最高优先级，不再变更）

1. **订单来源 A+B 都保留**：家长 App「我要报名」自助生成待收款单；工作室 Web 也能手动补建单。
   - 工作室手动建单**只能选本工作室联系人库的孩子**（在读 + 有历史订单，按昵称 / 家长手机搜索）；**全新孩子必须由家长先在 App 自助报名**。工作室只见教学必需字段。
2. **没有「部分收款」**：订单只有 `0 待收款 / 1 已收款 / 2 已取消`（退款终态聚合显示为已退款）。一次全款确认才发**全部**课时。
3. **凭证规则**：
   - 线上转账类（微信 / 支付宝 / 银行 / 收款码 / 其他）**必须上传凭证图**才能确认收款；
   - **现金可由工作室直接登记、免凭证**；
   - 家长能传付款凭证，工作室也能代传；支付方式仅作文字记录，**不跳转支付、不展示收款码**。
4. **佣金由工作室审核 + 线下打款 + 传凭证**，推广人按**工作室分别申请**、在 App 手动确认到账；**平台完全不碰钱**。一个老师可绑多个工作室，佣金按订单归属工作室分别结算。
5. **待收款单不自动取消**，仅工作室手动取消（线下收款慢，自动取消易误杀；待收款单不发课时、不占名额，挂着无副作用）。已取消单不参与重复报名拦截。
6. **没有任何自动确认**：退款 / 打款凭证**永久保留**，必须由收款方在 App 手动「确认收到」，无 N 天定时、无 `autoConfirmVouchers`。「未收到」走线下沟通，平台不仲裁。
7. **旧在线支付代码物理删除**（不是软下线）：删除微信支付下单 / 回调、余额付学费；**`wxCodeService` 必须保留**（小程序登录 code2session、小程序码海报）。Wallet 表保留，仅作佣金台账（不能充值、不能付学费）。
8. **SaaS 机构订阅本期只预留字段 / 菜单**（`studio_profile.subscription_expire_at`、`plan_tier`），不实现收费，后续再做。

## 一、三条目标状态机

### 1）购课订单 / 收款

```
家长 App 自助报名(模式A)  或  工作室 Web 手动建单(模式B, 仅联系人库孩子)
        │
        ▼
 ┌──────────────┐   家长线下转账后可上传「付款凭证(pay_method + voucher_images[] + note)」
 │ 0 待收款      │   → Payment(status=0 待确认)
 └──────┬───────┘
        │ 工作室核对到账，点「确认收款」
        │   · 现金：可直接登记，免凭证
        │   · 线上：必须已有凭证图（家长传或工作室代传）
        ▼
 ┌──────────────────────┐
 │ 1 已收款              │
 │  Payment status=1     │
 │  paid_amount=total    │
 │  发全部课时 + 班级人数+1│
 │  + LessonLog          │
 │  佣金记 CommissionRecord│
 │   status=1 待结算      │
 │  通知家长             │
 └──────────────────────┘

 旁支：
 · 凭证无效 → 工作室「驳回凭证」Payment status=2（带 reject_reason），订单仍为 0，家长可重新传
 · 工作室「取消订单」→ 2 已取消（仅手动；不发课时、不占名额）
```

- 支付方式枚举：`cash 现金 / wechat 微信转账 / alipay 支付宝转账 / bank 银行转账 / qrcode 收款码转账 / other 其他`；线上集合 = 除 cash 外全部。
- **重复报名拦截**：同一孩子同一课程存在 `status=0 待收款` 或 `status=1 已收款` 订单 / 有效权益时拒绝再建；已取消(2)、已退款不拦截。
- 订单列表 tab：**全部 / 待收款(0) / 已收款(1) / 已取消(2)**，已退款通过 refunds 聚合展示。

### 2）退款（对称：付款方传凭证，收款方手动确认）

```
家长申请退款(requested_lessons 课时数 + reason)
        │  Refund status=0 待审核
        ▼
 ┌──────────────┐
 工作室审核
  ├─ 驳回 → Refund status=2 已驳回(带 reject_reason)，家长可再次申请
  └─ 同意并线下退款：必须填 refund_method + 上传 voucher_images[]
        │  Refund status=1 待家长确认（processed_by / processed_at）
        ▼
 家长查看退款凭证
  ├─ 未收到 → 线下沟通，平台不仲裁（状态不变）
  └─ 「确认收到」→ Refund status=3 已退款（confirmed_at）
                 · 此时才扣减课时 / 写退款 LessonLog
                 · 订单聚合置为已退款、通知
```

> 关键：**工作室同意退款时不立即扣课时**；只有家长「确认收到」后才扣，避免「钱没到、课时先没」。

### 3）推广佣金 / 提现（工作室为审核打款主体）

```
订单全款确认收款
   │ 按该工作室课程的返利比例，生成 CommissionRecord status=1 待结算（不入钱包余额）
   ▼
推广人（老师/家长）按【工作室】发起提现 Withdrawal(status=1 申请中,
   带 studio_id + method 收款方式 + account 收款账户)
   ▼
工作室线下打款并上传 voucher_images[]
   ├─ 驳回 → Withdrawal status=4 已驳回(带原因)，对应金额退回可申请
   └─ 打款 → Withdrawal status=2 待确认（processed_by / processed_at）
                 │ 推广人查看凭证，手动「确认收到」
                 ▼
          Withdrawal status=3 已到账（confirmed_at）
            · 对应 CommissionRecord 置 2 已到账
            · 金额计入钱包台账（仅数字，不可消费/充值）
```

## 二、数据模型（已落库）

| 表 | 关键字段 / 改动 |
|---|---|
| **orders** | `status` 0待收款/1已收款/2已取消（退款聚合显示已退款）；`source` 0家长报名/1工作室建单；`pay_channel`、`paid_amount`、`paid_at`、`confirmed_by`；`class_id`（报名所选班级，已补 Order→Class belongsTo 关联 `as:"class"`） |
| **payments** | 一条=一次收款登记；`channel`+`pay_method`；`status` 0待确认/1已确认/2已驳回；`voucher_images` JSON 数组；`payer_note`；`upload_by` 0家长/1工作室；`confirm_by`、`reject_reason`、`paid_at` |
| **refunds** | `status` 0待审核/1待家长确认/2已驳回/3已退款；`refund_method`、`voucher_images` JSON、`reject_reason`、`processed_by/at`、`confirmed_at` |
| **withdrawals** | `status` 1申请中/2待确认/3已到账/4已驳回；`studio_id`、`method`、`account`、`voucher_images` JSON、`processed_by/at`、`confirmed_at`、`reject_reason` |
| **commission_records** | `status` 1待结算/2已到账；触发点=订单全款确认收款；按工作室归属 |
| **wallets** | 仅佣金台账：可申请 / 冻结中 / 已到账；**移除充值、移除余额付学费** |
| **studio_profile** | 预留 `subscription_expire_at`、`plan_tier`（SaaS 订阅，本期不实现） |

> **金额单位陷阱**：orders / payments / refunds 用**分**（int）；wallet / withdrawal / commission_record 用**元**（decimal(10,2)）。
> 图片数组统一存 OSS URL JSON（先写逻辑，OSS 后配置；未配置时落本地存储）。

## 三、接口清单

### 家长端 `/v1`（requireAuth）
- `POST /orders`：我要报名 → 生成 **0 待收款**单（必传 child_id / course_id / class_id），不发课时、不唤起支付。
- ~~`POST /orders/:id/pay`~~ **已删除**；微信支付 / 余额支付路由与控制器已物理删除。
- `POST /orders/:id/payment-voucher`：家长上传付款凭证 `{pay_method, voucher_images[], note}` → Payment status=0。
- `POST /orders/:id/cancel`：家长取消待收款单。
- `GET /orders`、`GET /orders/:id`：返回收款状态、班级、支付/凭证记录（已补 user/class/payments 全字段）。
- `POST /orders/:id/refunds`：申请退款（课时数 + 原因）。
- `POST /orders/refunds/:id/confirm`：**家长确认收到退款** → status=3，此时扣课时（P2）。
- `POST /commission/withdraw`：扩展 `{studio_id, method, account}`；按工作室申请（P3）。
- `POST /commission/withdraw/:id/confirm`：推广人确认收到打款 → status=3（P3）。

### 工作室 Web `/studio`（requireBackofficeAuth("studio")）
- `POST /studio/upload`：后台图片上传（内存 multer，字段名 `files`，≤9 张，folder 白名单含 `voucher`，返回 `{urls,storage}`）。
- `GET /studio/orders/contacts`：本工作室联系人库孩子（在读 + 历史订单，按昵称/手机搜索）。
- `POST /studio/orders`：手动建单（联系人库孩子/课程/班级[可后补]/金额分/方式/凭证/是否当场确认）。
- `GET /studio/orders`、`GET /studio/orders/:id`：列表 / 详情（含付款记录时间线、课时账本）。
- `POST /studio/orders/:id/payments/confirm`：确认收款（线上须有凭证、现金可直登）→ 发课时。
- `POST /studio/orders/:id/payments/reject`：驳回凭证（原因），订单仍待收款。
- `POST /studio/orders/:id/cancel`：手动取消订单。
- `POST /studio/refunds/:id`：`reject`（原因）/ `approve`（**必传 refund_method + voucher_images** → status=1，不扣课时）（P2）。
- `GET/PUT /studio/withdrawals/:id`：佣金审核，打款传凭证→2 / 驳回→4（P3）。

### 工作室 App `/v1/studio`（requireRole(3)）
- 本期收款/建单主要在 Web；App 端是否挂确认收款 / 建单路由按需后补。

### 平台 admin `/admin`
- **下线**平台代付、平台侧提现审核、`/admin/settlements` 代付动作（平台不碰钱）。
- 保留机构 / 课程 / 老师审核、监管举报、数据统计；订阅字段仅预留。

### 定时任务
- **删除** `autoCancelExpiredOrders`（决策 5：不自动取消）。
- **不新增** `autoConfirmVouchers`（决策 6：全部手动确认）。

## 五、分期

- **P0 后端 + Web 收款闭环** ✅
- **P1 家长端（iOS + 小程序）订单去支付化**：我要报名 → 待收款 → 上传付款凭证 → 工作室确认 → 课时到账的状态展示与凭证上传。
- **P2 退款对称闭环**：工作室同意必传退款凭证（Web）→ 家长 App「确认收到」才扣课时。
- **P3 佣金闭环**：按工作室申请、工作室打款传凭证、推广人确认；下线平台代付 / 余额支付残留入口。
- **P4 清理与合规**：协议文案、SaaS 订阅预留、旧入口清理复查。
